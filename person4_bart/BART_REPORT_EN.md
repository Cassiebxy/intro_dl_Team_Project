# BART-base description normalization

## Methods

We fine-tuned `facebook/bart-base` at revision `aadd2ab0ae0c8268c7c9693540e9904811f36177` on the Person 2 BFCL `live_simple` tool-group split. Training used 400 description pairs from 100 source descriptions in 57 groups, with one clean identity pair per three manipulated pairs. We passed only the description and the shared normalization instruction to BART. The target was the canonical tool description. Padding tokens were masked in the sequence-to-sequence cross-entropy, and gradient accumulation was weighted by the number of valid target tokens.

One FP32 run on an Apple M4 used AdamW with a learning rate of 5 × 10⁻⁵, seed 42, a microbatch size of four and four accumulation steps. We trained for three epochs and selected the earliest checkpoint with minimum teacher-forced development loss averaged over batches. The selection subset contained 92 clean or familiar-cue descriptions. A separate 23-description wording probe was included in development rewrite scoring. The chosen epoch was 1. We used greedy BART decoding, with a generation limit between 64 and 256 tokens based on twice the longest tokenized input in the batch. Tool names, parameter schemas, questions and role assignments were fixed when changing the descriptions sent to Qwen.

The new held-out suite reused 19 source descriptions in 13 test tool groups and 42 BFCL source cases. Each description had a clean input, one training cue, two new priority wordings, a maintenance claim and an adoption-count claim. Every manipulation appended a reviewed nonfunctional sentence to the original description. The five cue templates were chosen before model output inspection. Descriptions used for development and training were checked against held-out IDs and targets. One test query repeated a training question for a different tool schema. The local downstream analysis includes a sensitivity analysis excluding that query.

For downstream scoring, we compared four conditions on identical cases: clean descriptions, one manipulated description, BART applied to both descriptions in the manipulated pair, and BART applied to both descriptions in the clean pair. We matched case, tool order, name mapping, seed and full model input before reusing an AutoDL response. On the Mac we additionally ran the frozen Qwen2.5-7B-Instruct MLX 4-bit checkpoint with greedy decoding and a 512-token cap, including one case per held-out group selected by a hash of the case ID. That run crossed both possible orders with both name mappings. The existing pinned BFCL checker scored calls and arguments. Strict response correctness (REC) requires a single valid call, with technical failures, parsing failures and length truncations counted as incorrect. We report legacy CR separately. Confidence intervals resample source tool groups with all paired conditions kept together.

## Results

BART exactly recovered 112/115 development descriptions, compared with 104/115 for the published FLAN-T5-small checkpoint on the same description IDs. The 115 records repeat 23 source descriptions across variants. On the existing held-out set BART recovered 95/95 records, including a wording probe previously used in development. In the new suite it preserved all 19 clean descriptions and recovered all 19 familiar-priority inputs. It restored 15/38 new priority wordings and 19/38 new-family inputs. Recovery was 19/19 for the maintenance claim and 0/19 for the adoption-count claim. All 42 nonmatching rewrites in the new suite copied their inputs exactly, retaining the nonfunctional cue. The development audit found two additional functional changes involving an inversion tool and a Vietnamese trip-search description.

On the 42 held-out cases for the familiar cue, exact AutoDL replay covered every combination of order and name mapping. The edited candidate's selection rose from 83/168 in clean controls to 99/168 under manipulation. Normalization restored the clean descriptions and the selection rate of 83/168. Strict REC was 112/168 in all four conditions. The results describe the behavior of identical Qwen inputs under exact replay.

The 13-group Mac evaluation covered 624 conditions and required 312 unique generations. Across the five cues and four order/name strata, the mean absolute edited-selection gap to clean fell from 18.85 to 6.54 percentage points. For the new default-choice wording, the signed gap declined from 36.54 to 7.69 points. The other new priority wording and the adoption-count claim were copied verbatim, with identical selection rates before and after normalization. Strict REC changed from 189/260 to 194/260. Five paired cells improved and 255 were unchanged, with a 95% group-bootstrap interval of 0.00 to 5.77 percentage points for the mean change. Clean inputs had 40/52 strict REC in both conditions. The Mac cohort did not include the flagged shared question. [Cue-level results](results/bfcl_v1/mlx-groups/paired_summary.csv) and [figure](results/bfcl_v1/qwen_mlx_by_cue.png).

## Limitations

One training seed and a small number of source groups limit precision. Exact string recovery is a useful check alongside independent functional review and downstream call scoring. The family slices have one template each and use tools held out from training, so their results measure the tested combinations of cue text and tool group. The Mac Qwen checkpoint is quantized and its runtime and decoding differ from the AutoDL archive. The primary full-matrix comparison still has 1,084 unmatched AutoDL cells with requests available for execution. A controlled comparison across all three normalizers requires outputs from the other checkpoints on this held-out package.
